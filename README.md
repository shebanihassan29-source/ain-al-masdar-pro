# عين المصدر PRO — خادم الاشتراكات

خادم Node.js صغير يضيف إلى منصة «عين المصدر» طبقة الاشتراك: حسابات، تفعيل الاشتراك، مكتبة سحابية، وسيط ذكاء اصطناعي بمفتاح محفوظ على الخادم، ولوحة إدارة. النسخة الاحترافية نفسها (`private/pro.html`) **لا تُقدَّم إلا للمشترك الفعّال**.

**فكرة وتصميم: د. حسن الشيباني**

## البنية

```
المتصفح ──► الخادم (Express) ──► PostgreSQL         (حسابات، اشتراكات، مكتبات، حصص AI)
                 │
                 ├─ /            صفحة التسجيل والحساب وطلب التفعيل
                 ├─ /app         المنصة الاحترافية (تُخدَّم فقط لمن اشتراكه فعّال)
                 ├─ /api/*       المصادقة، المكتبة السحابية، وسيط الذكاء الاصطناعي
                 └─ /admin       لوحة الإدارة (بمفتاح ADMIN_KEY)
```

**مسار الدفع (يدوي عمدًا):** المشترك يدفع خارج المنصة (تحويل مصرفي/محفظة/نقدًا) ← يُدخل رقم العملية في صفحة حسابه ← تراجعه أنت في `/admin` وتضغط «قبول» ← يُفعَّل الاشتراك 30 يومًا. الضغط المتكرر لا يمنح أيامًا مرتين.

## متغيرات جديدة
`WATERMARK_SALT` (سر دائم لبصمة النسخ — لا تغيّره أبدًا) • `SUPPORT_CONTACT` (واتساب/بريد يظهر للمشترك).

## استعادة كلمة المرور (بلا بريد)
من `/admin` اضغط «رابط استعادة» أمام المشترك ← رابط لمرة واحدة صالح ساعة ← أرسله له (واتساب). تُخزَّن تجزئته فقط وتُبطَل جلساته القديمة عند التعيين.

## ما تغيّر في النسخة الاحترافية
- إزالة شعاري الجامعة والمركز، وترويسة التقارير باسم المشترك ومؤسسته (يبقى تذييل «فكرة وتصميم: د. حسن الشيباني»).
- ذكاء اصطناعي مدمج بلا مفاتيح (حصة يومية: 40 طلبًا، و200 لترجمة الاستعلامات التلقائية — قابلة للتعديل).
- مكتبة سحابية تتزامن بين الأجهزة.
- «مسودة مراجعة أدبيات» من المراجع المحفوظة، و«ملاحظات لكل المراجع» بضغطة.

## التشغيل محليًا
```bash
npm install
cp .env.example .env        # عدّل JWT_SECRET و ADMIN_KEY
npm run build:pro           # يولّد private/pro.html من النسخة المجانية ثم يطبّق tools/fix-pro.py (يفشل بصوت عالٍ إن تغيّر المصدر)
npm run dev                 # http://localhost:3000   (بدون DATABASE_URL يستخدم ملف JSON للتطوير فقط)
npm test                    # 35 فحصًا شاملًا (خادم حقيقي + ذكاء اصطناعي وهمي)
TEST_DATABASE_URL=postgres://... npm test   # الاختبار نفسه على PostgreSQL
```

## النشر على Render (خطوة بخطوة)

1. **مستودع خاص (Private):** أنشئ على GitHub مستودعًا **خاصًا** باسم `ain-al-masdar-pro` وارفع إليه محتوى هذا المجلد (بدون `node_modules` — يتجاهلها `.gitignore`). يجب أن يكون خاصًا لأن `private/pro.html` هو المنتج المدفوع.
2. **قاعدة البيانات:** أنشئ قاعدة PostgreSQL وانسخ رابط الاتصال (`postgres://...`).
   - Render يوفّر PostgreSQL مجانيًا لكن — بحسب علمي — بمدة محدودة؛ راجع شروطه الحالية قبل الاعتماد عليه.
   - بديل شائع: خطة مجانية من **Neon** أو **Supabase** (الرابط نفسه يعمل في `DATABASE_URL`).
3. **الخدمة:** في Render: `New → Blueprint` ← اختر المستودع الخاص (سيطلب ربط GitHub) ← سيقرأ `render.yaml`.
4. **المتغيرات (Environment):** أدخل `DATABASE_URL` و`AI_API_KEY` و`PAYMENT_INSTRUCTIONS` (بيانات الدفع التي ستظهر للمشتركين). أما `JWT_SECRET` و`ADMIN_KEY` فيولّدهما Render — **انسخ `ADMIN_KEY` من تبويب Environment**؛ هو كلمة مرور لوحة الإدارة.
5. **افتح** `https://<اسم-خدمتك>.onrender.com/healthz` ← يجب أن ترى `{"ok":true,"store":"postgres"}`.
6. **جرّب** التسجيل، ثم اطلب تفعيلًا، ثم ادخل `/admin` بالمفتاح واقبله، ثم افتح `/app`.

> خدمات Render المجانية «تنام» بعد نحو 15 دقيقة من الخمول، فيتأخر أول طلب بعدها. الخطة المدفوعة تزيل ذلك.

## الأمان — ما هو مطبَّق فعلًا
| الخطر | الإجراء |
|---|---|
| سرقة كلمات المرور | bcrypt بتكلفة 12، لا تُخزَّن كلمات مرور صريحة |
| تخمين كلمات المرور | حد 8 محاولات فاشلة/15 دقيقة لكل بريد + حد لكل IP، ورد بزمن ثابت تقريبًا للحسابات غير الموجودة |
| سرقة الجلسة | كوكي HttpOnly + SameSite=Lax + Secure في الإنتاج؛ «خروج من كل الأجهزة» يبطل كل الجلسات |
| CSRF | SameSite + طلبات JSON فقط + رفض أي طلب تغييري من Origin مختلف |
| XSS | سياسة CSP صارمة للصفحات العامة، وإدخال المستخدم يُعرض نصًا لا HTML |
| سرقة مفتاح الذكاء الاصطناعي | يبقى على الخادم فقط ولا يصل للمتصفح |
| إساءة استخدام الذكاء الاصطناعي | حصة يومية ذرّية لكل مشترك، وفشل المزوّد لا يستهلك الحصة |
| تفعيل مزدوج | قبول الطلب عملية ذرّية: الطلب المعالج لا يُقبل ثانية |
| الوصول للمنصة المدفوعة | `/app` والواجهات السحابية ترفض غير المشترك (401/402) |
| تسريب النسخة | كل نسخة تُخدَّم تحمل بصمة ترخيص خاصة بالمشترك (`am-licensee`) لتتبّع المصدر |

## حدود يجب أن تعرفها (بصراحة)
- **لا حماية مطلقة لصفحة ويب.** المشترك الذي يفتح `/app` يستطيع حفظ الصفحة من متصفحه. البصمة تتيح تتبّع التسريب وتردع، لكنها لا تمنعه. الحماية الحقيقية أن الميزات الثمينة (الذكاء الاصطناعي، المزامنة) تعمل على الخادم فلا تعمل بدون اشتراك.
- **النسخة المجانية علنية.** أي شخص يستطيع نسخ المستودع العام الحالي (وفيه الشعارات). لا يمكن منع ذلك تقنيًا؛ الترخيص في `LICENSE.md` هو الحماية القانونية.
- **التوسع:** الخادم بلا حالة داخلية، لكن محدِّدات الطلبات تعمل في ذاكرة النسخة الواحدة. عند تشغيل أكثر من نسخة ستحتاج مخزنًا مشتركًا (مثل Redis) لها. لآلاف المستخدمين المتزامنين غيّر الخطة والاستضافة.
- **النسخ الاحتياطي:** فعّل النسخ الاحتياطي في مزوّد قاعدة البيانات؛ فيها حسابات المشتركين ومكتباتهم.
- **الدفع والقانون:** لا توجد بوابة دفع مدمجة. تسجيل النشاط والضرائب وحماية بيانات المستخدمين أمور تخص وضعك القانوني في ليبيا؛ استشر مختصًا (أنا لست مستشارًا قانونيًا أو ماليًا).
- **لم يُختبر حتى الآن:** النشر الفعلي على Render، والاتصال بمزوّد ذكاء اصطناعي حقيقي (الاختبارات استخدمت خادمًا وهميًا)، وتشغيل الواجهة الاحترافية داخل متصفح فعلي.

## التحديثات المستمرة
1. عدّل النسخة المجانية (`ain-al-masdar/index.html`) كالمعتاد.
2. `npm run build:pro` (أو `python3 tools/build-pro.py <free.html> private/pro.html`) — يفشل بصوت عالٍ إن تغيّرت بنية الملف بما يكسر التحويل.
3. ارفع التعديل إلى المستودع الخاص؛ يعيد Render النشر تلقائيًا.

## ملفات المشروع
`server.js` الخادم • `db.js` التخزين (PostgreSQL / JSON للتطوير) • `public/` صفحات الحساب والإدارة • `private/pro.html` المنصة الاحترافية (مولَّدة) • `tools/` بناء النسخة الاحترافية • `test/smoke.js` الاختبارات • `render.yaml` تعريف النشر.
